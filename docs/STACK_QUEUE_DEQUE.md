# 스택·큐·덱의 개념과 활용

## 스택: 마지막에 넣은 항목부터 사용

스택은 LIFO(Last In, First Out) 순서입니다. 한쪽 끝에서만 `push`와 `pop`을 수행합니다. 접시를 위에 쌓고 위에서 꺼내는 동작과 같습니다.

```text
push A → push B → push C
pop 결과: C, B, A
```

함수 호출 스택, 괄호 검사, 깊이 우선 탐색, 편집기의 실행 취소에 사용합니다. 직접 구현한 `DynamicArray`의 `append`와 끝 `pop`을 조합하면 삽입은 분할 상환 O(1), 제거는 O(1)인 스택을 만들 수 있습니다. 이중 연결 리스트 한쪽 끝을 이용해도 두 연산 모두 O(1)입니다.

실행 취소 기능이라면 명령을 실행할 때 반대 동작을 스택에 넣고, 취소할 때 마지막 반대 동작을 꺼내 실행할 수 있습니다. 현재 Mini Redis에는 실행 취소 명령을 추가하지 않았습니다.

## 큐: 먼저 넣은 항목부터 사용

큐는 FIFO(First In, First Out) 순서입니다. 뒤쪽에 `enqueue`, 앞쪽에서 `dequeue`를 수행합니다. 먼저 도착한 요청을 먼저 처리하는 대기 줄과 같습니다.

```text
enqueue A → enqueue B → enqueue C
dequeue 결과: A, B, C
```

너비 우선 탐색, 작업 대기열, 이벤트 처리, 구독자별 메시지 버퍼에 사용합니다. 이 프로젝트의 이중 연결 리스트에서 `insert_back`과 `remove_front`를 조합하면 두 연산을 O(1)에 수행할 수 있습니다.

동적 배열의 0번 항목을 매번 삭제하면 나머지 항목 이동에 O(n)이 필요합니다. 배열로 큐를 만들 때는 앞 인덱스를 별도로 유지하거나 원형 버퍼를 사용하는 이유입니다.

Pub/Sub를 확장한다면 구독자마다 큐를 두고, 발행된 메시지를 뒤에 넣고 읽을 때 앞에서 꺼내는 방식으로 전달 순서를 유지할 수 있습니다. 현재 구현은 Pub/Sub를 포함하지 않습니다.

## 덱: 양쪽 끝에서 넣고 꺼내기

덱은 Double-Ended Queue의 줄임말입니다. 앞·뒤 양쪽에서 삽입과 제거를 허용합니다. 스택과 큐의 동작을 모두 표현할 수 있습니다.

| 동작 | 이중 연결 리스트 메서드 | 비용 |
| --- | --- | --- |
| 앞에 추가 | `insert_front` | O(1) |
| 뒤에 추가 | `insert_back` | O(1) |
| 앞에서 제거 | `remove_front` | O(1) |
| 뒤에서 제거 | `remove_back` | O(1) |

양쪽 끝을 유지하는 이중 연결 리스트는 덱에 적합합니다. 단일 연결 리스트는 뒤쪽 노드의 이전 노드를 바로 찾을 수 없어 일반적인 뒤 삭제에 O(n)이 필요합니다.

## LRU와의 연결

LRU는 가장 최근 사용한 키를 앞에 두고 오래 사용하지 않은 키를 뒤에 둡니다. 앞·뒤를 다룬다는 점은 덱과 비슷하지만, 이미 저장된 키를 중간에서 꺼내 앞으로 옮기는 기능도 필요합니다.

```text
최근                                 오래됨
front → C ↔ B ↔ A ← back

GET B 성공
front → B ↔ C ↔ A ← back

메모리 부족 → back의 A 제거
```

덱만으로 임의 키를 찾으면 O(n)입니다. 이 프로젝트는 사용자 정의 해시맵에 LRU 노드 참조를 보관해 평균 O(1)에 노드를 찾고, 연결을 바꿔 O(1)에 앞으로 옮깁니다. 따라서 덱의 양 끝 연산과 해시맵의 조회를 함께 이해하는 것이 LRU 설계의 핵심입니다.

현재 LRU는 `GET`과 `SET`에 성공했을 때만 순서를 갱신합니다. TTL 확인이나 존재 여부 확인은 사용 순서를 바꾸지 않습니다.
